# テストケース: stickyBookSearch（本一覧の絞り込みを画面の上に残す）

- ID の略号: `SS`
- PBI: #37
- 書いた人: Sho Nakata
- もとにした資料: [画面設計書](../../docs/ap/BookListPage/Screen_design.md)

帯を画面の上に貼り付けること自体（`position: sticky`）は CSS で行うので、jsdom では確かめられない。
ブラウザで 390・768・1280px の幅を撮って確かめた（PR に記載）。ここでは、帯の中身と、帯の高さに合わせて
スクロールで止まる位置を下げる処理を確かめる。

jsdom には `ResizeObserver` が無いので、テストの中で作り物に差し替え、帯の大きさが変わったことを知らせる。
jsdom では要素の高さ（`offsetHeight`）がいつも 0 なので、帯の高さもテストの中で決める。

## BookListPage（`frontend/src/pages/BookListPage.tsx`）

検索ボックスと場所・ステータスの選択肢を、上に残す帯（`.book-search`）にまとめ、
帯の高さの分だけ、ページのスクロールで止まる位置（`scroll-padding-top`）を下げる。

| ID    | 観点 | 条件・入力                                         | 期待する結果                                                                                            |
| ----- | ---- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| SS-01 | 正常 | 本の一覧を読み込む                                 | 検索ボックスと、場所・ステータスの選択肢が、どちらも同じ帯（`.book-search`、`role="search"`）の中にある |
| SS-02 | 正常 | 画面を開く                                         | 帯（`.book-search`）の大きさの監視を始める                                                              |
| SS-03 | 正常 | 帯の高さが 72px だと知らせる                       | ページ（`html`）の `scroll-padding-top` が `72px` になる                                                |
| SS-04 | 状態 | 72px のあと、帯の高さが 204px に変わったと知らせる | `scroll-padding-top` が `204px` に変わる（選択肢が折り返して帯が高くなったとき）                        |
| SS-05 | 正常 | 帯の高さを知らせたあと、画面を離れる               | 監視をやめ、`scroll-padding-top` を消す（ほかの画面に残さない）                                         |
| SS-06 | 境界 | `ResizeObserver` が無い環境で画面を開く            | エラーにならずに一覧を表示し、`scroll-padding-top` を付けない                                           |
