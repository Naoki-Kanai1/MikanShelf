# テストケース: responsiveLayout（画面の幅に合わせたメニューの切り替え）

- ID の略号: `RL`
- PBI: #22
- 書いた人: Sho Nakata
- もとにした資料: `docs/UI_design.svg`、`docs/Responsive_design.md`（5 つの区分の決まり）

画面の幅でどちらのメニューを出すかは CSS（`AppShell.css` の `@media`）で決まる。テストの画面（jsdom）は
CSS の幅による切り替えをしないため、見た目の切り替えは単体テストでは確かめない（スクリーンショットで確認する）。
単体テストでは、CSS が切り替えに使うクラス名と、それぞれのメニューの中身を確かめる。

## NavigationBar（`frontend/src/components/NavigationBar.tsx`）

スマホ版のメニュー。画面の下に固定する。

| ID    | 観点 | 条件・入力                         | 期待する結果                                                                             |
| ----- | ---- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| RL-01 | 正常 | 表示する                           | 「メニュー」という名前のナビゲーションに、本一覧・借りている本・蔵書リクエストの順に並ぶ |
| RL-02 | 正常 | 表示する                           | リンク先が `/books`、`/loans`、`/requests` になる                                        |
| RL-03 | 状態 | `/books` を開いている              | 「本一覧」だけが選択中になる（`aria-current="page"` とクラス `active`）                  |
| RL-04 | 状態 | `/books/3`（本詳細）を開いている   | 「本一覧」が選択中になる（URL が `/books` で始まる）                                     |
| RL-05 | 状態 | `/loans/1`（貸出詳細）を開いている | 「借りている本」だけが選択中になる                                                       |
| RL-06 | 境界 | `/`（ホーム）を開いている          | どの項目も選択中にならない                                                               |
| RL-07 | 正常 | 表示する                           | 各項目に、印（アイコン）が1つずつ付く                                                    |
