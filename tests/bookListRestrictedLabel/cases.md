# テストケース: bookListRestrictedLabel（本一覧画面の「持ち出し禁止」の印）

- ID の略号: `RL`
- PBI: #26（持ち出し禁止の表示箇所をステータスの位置に変更する）
- 書いた人: kanai-naoki
- もとにした資料: [画面設計書](../../docs/ap/BookListPage/Screen_design.md)

持ち出し禁止の本は借りられないので、いつも棚にある。そのため本一覧では「棚にある」の代わりに「持ち出し禁止」の印を、状態の印の位置に1つだけ出す。
API（`GET /api/books`）の応答は、テストの中で作り物に差し替える（本物のサーバーと DB は使わない）。
色や位置などの見た目は、ブラウザで別に確かめる。

## StatusChip（`frontend/src/components/StatusChip.tsx`）

本の貸出状態の印。`restricted` が true で棚にあるときは「持ち出し禁止」を出す。

| ID    | 観点 | 条件・入力                                    | 期待する結果                                                                                           |
| ----- | ---- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| RL-01 | 正常 | `status` が `available`、`restricted` が true | 「持ち出し禁止」だけを表示し、「棚にある」は出さない。`status-chip--restricted` のクラスが付く         |
| RL-02 | 異常 | `status` が `borrowed`、`restricted` が true  | 実際の状態の「誰かが借用中」を表示し、`status-chip--borrowed` のクラスが付く（データの誤りを隠さない） |
| RL-03 | 境界 | `restricted` を渡さない、または false         | 今までどおり「棚にある」を表示し、`status-chip--restricted` のクラスは付かない                         |
| RL-04 | 状態 | `status` が `available`、`restricted` が true | 色だけでなく、印（アイコン）が1つ付く。`className` を渡すと、もとのクラスに加えて付く                  |

## BookListPage（`frontend/src/pages/BookListPage.tsx`）

本の行の右側に、状態の印を1つ出す。

| ID    | 観点 | 条件・入力                                               | 期待する結果                                                            |
| ----- | ---- | -------------------------------------------------------- | ----------------------------------------------------------------------- |
| RL-05 | 正常 | `is_restricted` が `1` の本（`available`）               | 行の状態の印は1つだけで、その文字は「持ち出し禁止」。「棚にある」は無い |
| RL-06 | 状態 | `is_restricted` が `0` の本（`available` と `borrowed`） | それぞれ「棚にある」「誰かが借用中」を出し、「持ち出し禁止」は無い      |
